# linux Provider

Manages files, packages, users, services and other settings of a Linux host, either the machine running Terraform (`mode = "local"`) or a remote host over SSH (`mode = "ssh"`).

Everything runs through `/bin/sh` with standard tools (coreutils, `sed`, `systemctl`), so the host needs no agent. GNU and BusyBox userlands are supported.

## Example Usage

```terraform
# Remote host over SSH, as root through sudo.
provider "linux" {
  mode = "ssh"
  sudo = true

  ssh = {
    host        = "10.0.0.10"
    user        = "deploy"
    private_key = file("~/.ssh/id_ed25519")

    # Optional jump host.
    bastion = {
      host = "bastion.example.com"
      user = "jump"
    }
  }
}

# The machine running Terraform.
provider "linux" {
  alias = "local"
  mode  = "local"
}
```

## Modes

* `local`: commands run on the machine running Terraform. Use it when Terraform runs on the host it manages.
* `ssh`: commands run on a remote host. One connection is opened per provider and shared by all resources, with at most `ssh.max_sessions` commands at the same time. A broken connection is re-established.

`mode` defaults to `ssh` when the `ssh` attribute is set, and to `local` otherwise. Use [provider aliases](https://developer.hashicorp.com/terraform/language/providers/configuration#alias-multiple-provider-configurations) to manage several hosts.

## SSH authentication

The provider tries, in this order, the configured `private_key` (or `private_key_path`), the keys of the SSH agent when `agent` is `true` (the default), then `password`, also used to answer keyboard-interactive prompts.

Host keys are verified against `~/.ssh/known_hosts`, or `known_hosts_file`. Pin a key with `host_key` instead, for instance one produced by the resource that creates the host. `insecure_ignore_host_key` disables the verification: only use it for tests.

## Privileges

With `sudo = true`, every command runs as root through `sudo`. When `sudo` asks for a password, set `sudo_password`: it is sent on the standard input of `sudo`, never on a command line. Hosts whose `sudoers` require a TTY (`Defaults requiretty`) are not supported.

## What destroying a resource does

Resources undo what they did, but never delete what existed before them:

| Resource | On destroy |
|----------|------------|
| `linux_file`, `linux_symlink`, `linux_cron_job`, `linux_file_block`, `linux_ssh_authorized_key` | Removed. |
| `linux_file_line` | Line removed, unless `remove_on_destroy = false`. A line it replaced is not restored. |
| `linux_directory` | Removed when empty, or with its content when `force_destroy = true`. |
| `linux_patch` | Patch reverted, unless `revert_on_destroy = false`. |
| `linux_package`, `linux_user`, `linux_group` | Removed only if the resource created it: an existing package, user or group it adopted is left in place. |
| `linux_sysctl` | Line removed from the sysctl file; the current value is left. |
| `linux_systemd_unit` | Left as it is, unless `revert_on_destroy = true`. |
| `linux_sed`, `linux_hostname` | Left as they are. |
| `linux_command` | Runs the `delete` script, if any. |

Unset attributes fall back to environment variables:

| Attribute | Environment variable |
|-----------|----------------------|
| `mode` | `LINUX_MODE` |
| `sudo` | `LINUX_SUDO` |
| `sudo_password` | `LINUX_SUDO_PASSWORD` |
| `ssh.host` | `LINUX_SSH_HOST` |
| `ssh.port` | `LINUX_SSH_PORT` |

## Schema

### Optional

- `mode` (String) Where commands run: `local` (the machine running Terraform) or `ssh`. Defaults to `ssh` when `ssh` is set, `local` otherwise. Environment variable: `LINUX_MODE`.
- `ssh` (Attributes) Connection to the remote host, used when `mode` is `ssh`. (see [below for nested schema](#nestedatt--ssh))
- `sudo` (Boolean) Run every command as root through `sudo`. Environment variable: `LINUX_SUDO`.
- `sudo_password` (String, Sensitive) Password `sudo` asks for. Leave unset when `sudo` does not ask for one (`NOPASSWD`). It is sent on the standard input of `sudo`, never on a command line. Environment variable: `LINUX_SUDO_PASSWORD`.

### Nested Schema for `ssh`

Optional:

- `agent` (Boolean) Authenticate with the keys of the SSH agent listening on `SSH_AUTH_SOCK`. Defaults to `true`.
- `bastion` (Attributes) Jump host used to reach `host`. (see [below for nested schema](#nestedatt--ssh--bastion))
- `host` (String) Host name or IP address. Required. Environment variable: `LINUX_SSH_HOST`.
- `host_key` (String) Expected public key of the host, in `authorized_keys` format (`ssh-ed25519 AAAA...`). Takes precedence over `known_hosts_file`. Environment variable: `LINUX_SSH_HOST_KEY`.
- `insecure_ignore_host_key` (Boolean) Accept any host key. This makes the connection vulnerable to interception: use it only for tests. Environment variable: `LINUX_SSH_INSECURE_IGNORE_HOST_KEY`.
- `known_hosts_file` (String) known_hosts file used to verify host keys, for the host and the bastion. Defaults to `~/.ssh/known_hosts`. Environment variable: `LINUX_SSH_KNOWN_HOSTS_FILE`.
- `max_sessions` (Number) Maximum number of commands run at the same time over the connection. Keep it below the `MaxSessions` setting of the SSH server (10 by default). Defaults to `5`.
- `password` (String, Sensitive) Password, for password and keyboard-interactive authentication. Environment variable: `LINUX_SSH_PASSWORD`.
- `port` (Number) SSH port. Defaults to `22`. Environment variable: `LINUX_SSH_PORT`.
- `private_key` (String, Sensitive) Private key in PEM or OpenSSH format. Environment variable: `LINUX_SSH_PRIVATE_KEY`.
- `private_key_passphrase` (String, Sensitive) Passphrase of an encrypted private key. Environment variable: `LINUX_SSH_PRIVATE_KEY_PASSPHRASE`.
- `private_key_path` (String) Path to the private key, on the machine running Terraform. `~` expands to the home directory. Environment variable: `LINUX_SSH_PRIVATE_KEY_PATH`.
- `timeout` (String) Maximum time to establish the connection, as a Go duration such as `30s` or `1m`. Defaults to `30s`.
- `user` (String) User to log in as. Defaults to `root`. Environment variable: `LINUX_SSH_USER`.
